# Model card: FlowGuard CICIDS2017 bundle

Format inspired by Mitchell et al., *Model Cards for Model Reporting* (FAT* 2019).
All numbers come from [`reports/metrics.json`](../reports/metrics.json) and are regenerated by
`flowguard evaluate`.

## Model details

| | |
|---|---|
| Components | Histogram Gradient Boosting and Random Forest classifiers (attack family), MLP autoencoder and Isolation Forest (benign-only anomaly detectors) |
| Primary configuration | Hybrid: Gradient Boosting (alerts at 0.1% FPR) OR autoencoder (leads at 1% FPR) |
| Input | 65 bidirectional flow statistics computed by FlowGuard's CICFlowMeter-compatible flow meter |
| Output | Attack family + calibrated alert decision; anomaly score with per-feature explanation |
| Framework | scikit-learn; artifacts are joblib files verified by SHA-256 before loading |
| Training data | Improved CICIDS2017 (Engelen et al., 2022), 60/20/20 stratified split after cleaning |
| Licence | MIT |

## Intended use

* Research, teaching and portfolio demonstration of ML-based network intrusion detection.
* Offline analysis of packet captures and replay of labelled traffic in a lab.
* A starting point for experiments on train/serve parity, threshold calibration and
  zero-day evaluation.

**Out of scope:** blocking traffic or making any automated decision on a production network.
The models are trained on one lab network from 2017; deploying them elsewhere requires
re-training on local traffic and a fresh calibration of thresholds.

## Factors and metrics

* **Detection rate** (recall on attack flows) at a **fixed false-positive budget**, because
  the base rate of attacks is low in practice and analysts' time is the scarce resource.
* **Per-family detection**, since an aggregate score hides weak families (rare classes,
  web attacks).
* **Leave-one-family-out detection**, a proxy for behaviour on novel attacks.
* ROC-AUC / PR-AUC are reported for completeness but do not drive any decision.

## Evaluation data

The held-out 20% test split (342,536 flows, 56,378 attacks), never used for training or
threshold calibration. Thresholds are calibrated on the separate validation split.

## Results

See [`reports/REPORT.md`](../reports/REPORT.md) for every table and figure. Summary:

| Metric (test split) | Value |
|---|---:|
| Gradient Boosting detection rate at 0.1% FPR budget | 99.998% (test FPR 0.096%) |
| Autoencoder detection rate at 1% FPR budget | 10.8% (test FPR 1.04%) |
| Hybrid detection rate / FPR / precision | 99.998% / 1.11% / 94.7% |
| Mean detection of a held-out family: supervised / autoencoder / hybrid | 23.4% / 16.7% / 37.4% |
| Multi-class macro-F1, operational / argmax | 0.80 / 0.92 |
| HTTP flood probe: detection when only the close and segmentation change | 0% |

## Ethical considerations and caveats

* **Dataset age and realism.** CICIDS2017 is synthetic lab traffic from 2017. Attack tools,
  protocols (e.g. QUIC, TLS 1.3) and benign profiles have changed since.
* **Optimistic in-distribution scores.** Near-perfect supervised scores reflect that test
  attacks come from the same tool runs as training attacks. The zero-day experiment shows
  how much detection drops when a family is unseen.
* **Per-flow blind spots.** Volumetric attacks (DoS, DDoS) and credential brute force consist
  of individually normal-looking flows; per-flow anomaly detection cannot see them.
  Aggregating behaviour per host and per time window is the next step.
* **Feature-space evasion.** An attacker who knows the features can shape traffic (padding,
  timing jitter) to look benign. No adversarial robustness is claimed.
* **Privacy.** Only flow statistics are used: no payload inspection. IP addresses appear in
  alerts, so alert files should be handled as security logs.
